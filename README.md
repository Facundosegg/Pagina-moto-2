# RUTA NEA MOTOS — sitio web

Sitio de venta de motos: catálogo con filtros, formularios que arman el
mensaje y lo mandan directo por WhatsApp, y un botón de "Cargar moto"
para vos como administrador — con tu usuario y contraseña — que carga
motos y se ve al instante para cualquiera que entre al sitio, desde
cualquier celular.

---

## Antes que nada: por qué no se te actualizaba la página al editar `data.js`

Casi seguro es uno de estos tres motivos:

1. **Publicaste con "Netlify Drop" (arrastrando la carpeta `dist`).**
   Ese método sube una foto fija del sitio en ese momento. Editar
   `data.js` después **no cambia nada online** hasta que corras de nuevo
   `npm run build` y vuelvas a arrastrar la carpeta `dist` actualizada.
   Es el motivo más común. Si vas a estar tocando contenido seguido, te
   conviene la Opción B de más abajo (GitHub + Vercel), que se actualiza
   sola con cada cambio.

2. **Estás probando en local con `npm run dev` y el navegador tiene
   una versión vieja en caché.** Probá un refresco forzado
   (`Ctrl + Shift + R` en Windows/Linux, `Cmd + Shift + R` en Mac).

3. **El cambio no se subió realmente** (si usás GitHub, revisá que el
   `git push` se haya hecho, y que en el panel de Vercel/Netlify diga
   "Published" o "Ready" y no "Building" o "Failed").

Con el cambio que hicimos ahora, esto deja de ser un problema para el
catálogo de motos (ya no vive en `data.js`, vive en una base de datos y
se actualiza solo, sin build ni redeploy). Pero `data.js` sigue siendo
donde vive tu WhatsApp, dirección y horario — para esos datos, el punto
1 sigue aplicando.

## 1. Cargar motos con perfil de administrador (paso a paso)

Esto usa **Supabase**: una base de datos gratuita en la nube. Se
configura una sola vez. Después, vos entrás al sitio con tu usuario y
contraseña, cargás/editás/borrás motos desde ahí, y se ve al instante
para todos los visitantes — sin tocar código, sin rebuild, sin resubir
nada.

### Paso 1 — Creá el proyecto en Supabase

1. Entrá a **https://supabase.com** y creá una cuenta gratis (podés
   entrar directo con GitHub o Google).
2. "New Project". Elegí un nombre (ej. `ruta-nea-motos`) y una
   contraseña para la base (guardala, no la vas a necesitar de nuevo
   para esto, pero por las dudas). Región: la más cercana, `South
   America (São Paulo)` si está disponible.
3. Esperá un par de minutos a que el proyecto termine de crearse.

### Paso 2 — Creá la tabla de motos

1. En el menú de la izquierda, andá a **SQL Editor**.
2. Pegá esto y tocá **Run**:

```sql
create table motos (
  id bigint generated by default as identity primary key,
  marca text not null,
  modelo text not null,
  anio int4,
  estado text not null default 'usado',
  cc int4,
  km int4,
  precio numeric not null,
  moneda text not null default 'ARS',
  destacado text,
  image_url text,
  created_at timestamptz not null default now()
);

alter table motos enable row level security;

create policy "Cualquiera puede ver el catálogo"
on motos for select
using ( true );

create policy "Solo admins logueados pueden cargar motos"
on motos for insert
to authenticated
with check ( true );

create policy "Solo admins logueados pueden editar motos"
on motos for update
to authenticated
using ( true );

create policy "Solo admins logueados pueden borrar motos"
on motos for delete
to authenticated
using ( true );
```

Esto crea la tabla y las reglas de seguridad: cualquiera puede **ver**
el catálogo (así funciona el sitio para tus clientes), pero solo alguien
**logueado** puede cargar, editar o borrar.

3. (Opcional, recomendado) Activá que los cambios se vean en vivo sin
   recargar la página: **Database → Replication**, buscá la tabla
   `motos` y activá el switch. Si no lo activás, el sitio igual funciona
   perfecto — solo que un visitante que ya tenía la página abierta ve la
   moto nueva recién si refresca.

### Paso 2.1 — Creá el espacio para las fotos

Esto es lo que te permite subir fotos tocando un botón, en vez de tener
que buscar el link en otra página.

1. En el menú de la izquierda, andá a **Storage**.
2. Tocá **New bucket**.
3. Nombre: escribí exactamente `motos` (así, en minúscula).
4. Activá el switch **Public bucket** (importante: si no lo activás,
   las fotos no se van a poder ver en el sitio).
5. Tocá **Create bucket**.
6. Andá de nuevo a **SQL Editor → New query**, pegá esto y tocá **Run**:

```sql
create policy "Cualquiera puede ver las fotos"
on storage.objects for select
using ( bucket_id = 'motos' );

create policy "Solo admins logueados pueden subir fotos"
on storage.objects for insert
to authenticated
with check ( bucket_id = 'motos' );

create policy "Solo admins logueados pueden reemplazar fotos"
on storage.objects for update
to authenticated
using ( bucket_id = 'motos' );

create policy "Solo admins logueados pueden borrar fotos"
on storage.objects for delete
to authenticated
using ( bucket_id = 'motos' );
```

Mismo criterio que con la tabla: cualquiera puede ver las fotos (para
que se vean en el catálogo), pero solo un administrador logueado puede
subir, reemplazar o borrar.

### Paso 3 — Creá tu usuario de administrador

1. Andá a **Authentication → Users**.
2. **Add user → Create new user**.
3. Cargá tu email y una contraseña. Marcá **Auto Confirm User** para no
   tener que confirmar por mail.
4. Guardá ese email y contraseña — son los que vas a usar en el sitio
   para entrar como administrador.

Importante: **no** hay una pantalla de registro público en el sitio (a
propósito, para que nadie más pueda crearse una cuenta). Los usuarios
administradores se crean solo desde acá, en el panel de Supabase.

### Paso 4 — Conectá el sitio a tu proyecto

1. En Supabase, andá a **Project Settings → API**.
2. Copiá el **Project URL** y la **anon public key**.
3. En la carpeta del proyecto, copiá el archivo `.env.example` y
   renombrá la copia a `.env` (sin ".example").
4. Completá `.env` con esos dos datos:

```
VITE_SUPABASE_URL=https://tu-proyecto.supabase.co
VITE_SUPABASE_ANON_KEY=tu-clave-anon-publica
```

5. Si publicás con Netlify o Vercel, también tenés que cargar esas
   mismas dos variables en el panel de esos servicios (no alcanza con
   tenerlas solo en tu computadora):
   - **Netlify**: Site settings → Environment variables.
   - **Vercel**: Project Settings → Environment Variables.

### Paso 5 — Probalo

```bash
npm install
npm run dev
```

Entrá al sitio, tocá el ícono de caja (📦) arriba a la derecha, iniciá
sesión con el usuario que creaste en el Paso 3, y cargá tu primera moto.
Sacá el catálogo de ejemplo si ya no lo necesitás (con el mismo botón,
tacho de basura en cada fila).

## 2. Editar tus datos de contacto

`CONFIG` y `MARCAS`, en `src/data.js`, siguen siendo texto que se edita
a mano: nombre del negocio, WhatsApp, dirección, horario y redes. No
hace falta saber programar, solo respetar las comillas y las comas.
Después de editarlo hay que volver a publicar (ver la sección
"Publicarlo en internet" para saber cómo, según el método que uses).

`whatsappNumber` tiene que tener el formato: código de país (54) + 9 +
código de área sin el 0 + número sin el 15. Ejemplo, para (0362)
15-400-0000: `5493624000000`.

## 3. Probarlo en tu computadora

Necesitás [Node.js](https://nodejs.org) (versión 18 o superior).

```bash
npm install
npm run dev
```

Te va a dar una dirección tipo `http://localhost:5173` para abrir en el
navegador.

## 4. Publicarlo en internet (gratis)

### Opción A — Netlify Drop (simple, pero hay que resubir a mano)

1. `npm install` y `npm run build` → genera la carpeta `dist`.
2. Entrá a **https://app.netlify.com/drop** y arrastrá la carpeta
   `dist`. Te da una URL pública al instante.
3. **Importante**: agregá las variables de entorno del Paso 4 de arriba
   en Site settings → Environment variables, y volvé a hacer
   `npm run build` + arrastrar `dist` una vez que las cargues.
4. Si más adelante cambiás algo de `src/data.js` (WhatsApp, horario,
   etc.), repetís: `npm run build` y volvés a arrastrar `dist`. El
   catálogo de motos **no** necesita este paso — ese se actualiza solo,
   ya que vive en Supabase.

### Opción B — GitHub + Vercel (recomendada, se actualiza sola)

1. Cuenta gratis en **github.com** y en **vercel.com** (podés entrar a
   Vercel directo con la cuenta de GitHub).
2. Subí esta carpeta como repositorio nuevo en GitHub (se puede
   arrastrar los archivos desde la web, con "Add file → Upload files",
   sin usar la terminal).
3. En Vercel: "Add New… → Project", elegís el repositorio, y en
   **Environment Variables** cargás `VITE_SUPABASE_URL` y
   `VITE_SUPABASE_ANON_KEY` (los del Paso 4). Después "Deploy".
4. Te da una URL pública. De acá en adelante, cualquier cambio en
   `src/data.js` que subas a GitHub (botón de lápiz en el archivo, ahí
   mismo en la web) republica el sitio solo, en menos de un minuto.
   El catálogo de motos sigue sin necesitar ningún redeploy.

Si querés un dominio propio (ej. `rutaneamotos.com.ar`), tanto Netlify
como Vercel tienen una opción para conectarlo, una vez que lo compres
en NIC Argentina o en cualquier registrador.
